# 附近自动烹饪（保鲜优先）

《饥荒联机版》独立模组，版本 **1.0.2**。每口锅记住自己的食材配比，按指定锅数或连续制作；从附近储藏容器和地面取料，完成后优先存入保鲜容器。无需新增建筑或制作物品。

## 安装与使用

通过 Steam 创意工坊订阅，或按下面的方式手动安装。工坊版与本地版选一个启用，避免重复加载。

1. 把 `nearby_autocook` 整个文件夹复制到游戏 `Don't Starve Together/mods/`。世界的“服务器模组”中启用“附近自动烹饪（保鲜优先）”。
2. **房主和加入游戏的玩家均需安装**，因为模组包含数量输入控件和网络飞行效果。本地安装包不会自动通过创意工坊分发。
3. 打开锅，像原版一样放好一锅食材，每格一份。例如“大肉 ×1、浆果 ×3”，就放一个肉格和三个浆果格。
4. 在原版“烹饪”按钮下方填写 **数量**，再点原版 **烹饪**。默认 `1` 锅，`1–9999` 为有限锅数，`0` 为连续烹饪。数量**包含当前手动放入的第一锅**。
5. 后续把同种食材放进附近的箱子、冰柜、地窖或地面，模组就会按第一锅的配比续做，煮好优先送入保鲜容器。

**开始烹饪只需填数量，再点原版烹饪，不需要另行记录配方。** 手动放进锅的食材就是本次配方，原版“烹饪”同时启动本锅和后续批次。空闲时只修改数量不会提前消耗食材。每次重新手动放料并点击原版烹饪，都会以这次实际放入的食材作为新配方。

例如数量填 `3`，第一锅手动放料，后面再自动补料煮两锅。达到数量即停止续做；不足一整锅材料时等待补充。原版锅每锅仍为四份食材。

### 中途修改数量或取消配方

自动烹饪正在进行、等待关闭锅或缺料等待时，**右键锅 → 调整烹饪**。即使原版锅正在烹饪、不能打开食材格，也可以使用这个入口。

- 数量框显示**剩余锅数**；回车或移开输入焦点即应用。数字从现在起计算，包含正在煮或尚未收取的当前一锅，已经完成并收取的不再计入。`0` 为连续。
- 例如正在煮时改成 `1`，这锅结束就停止；改成 `3`，这锅之后再做两锅。缺料、锅内没有在制料理时填 `3`，则接下来做三锅。
- 点击 **取消配方** 立即停止后续取料并清除当前配方，数量回到 `1`。已经下锅的食材按原版继续煮完，成品照常优先收存，不退料、不丢失。
- 想换菜谱：先取消配方，等当前一锅完成，再放入新食材并点原版烹饪。无需另设配方列表。
- Esc 或关闭面板只关闭界面，不取消烹饪。左键打开/收获保留原版行为。

原版锅界面中的数量也会显示剩余锅数；已有任务时修改立即生效。房主与客户端都需更新到同一版本。

## 取料和成品去向

- 默认范围 **12 距离，约三块地皮宽**，可设 4 / 8 / 12 / 16 / 24。
- 储藏优先、地面其次；储藏按距离、箱内按槽位顺序。只使用记录的同名食材，不自动替换生熟食材或其他等价配方。
- 每锅先检查缺少的食材是否全部足够，再按单件取出。缺料会等待补充，不扣掉一半材料；多个锅共享储藏时依次处理，不重复占用同一份。
- 成品按容器对该食物的保鲜能力排序：负倍率返鲜、已知冰柜、一般冷藏，再到普通箱子；同档选近处。满了或不接受该食物时顺次寻找下一个，最后放锅旁地面。
- 原版食物的出品数量、食材鲜度折算和烹饪耗时均保留，例如一次软糖的多份产出。模组不会主动给食物增加鲜度。
- 食材飞向锅、料理飞向储藏处是纯视觉动画。真实物品同步扣除/存放，飞行特效没有物品组件，也不会写入存档；因此不存在“物品飞到半空时退出就消失”的中间运输状态。
- 飞行采用馨食记的高抛参数：起落偏移 `3.2`、高度参数 `6.5`、重力 `25`、速度倍率 `1.1`。独立视觉实体使用原版 `Physics` 与 `complexprojectile` 飞行，客户端接收同一条服务端轨迹；该实体没有食材、堆叠、伤害或存档组件。

冰箱、冰柜、地窖和箱子**打开时也能正常供给食材、接收料理**。玩家手动取放与自动取料共用原生容器接口，自动流程会在扣料前再次核对物品、槽位和数量。1.0.0 的“避开正在打开的储藏容器”设置已移除，旧世界保留该选项也不会阻止取料或存放。

玩家打开锅时自动补料仍会等待；其他玩家打开着的锅不能被设置指令强行启动。背包、切斯特等生物容器、远程共享容器、烧毁/着火/只读容器和其他生产设备不作为材料箱。

## 冰柜、地窖及烹饪建筑兼容

| 类型 | 接入方式 |
| --- | --- |
| 原版烹饪锅、便携烹饪锅 | 使用原生 `stewer` 开始/收获；便携厨具保留沃利配置权限 |
| 原版冰箱、盐盒、普通箱子 | 尊重容器实际收纳限制；盐盒不接受的成品不会硬塞 |
| Arcadiea 冰柜，`mega_freezer`（工坊 1872917938） | 标准储物接口，并明确优先于普通冰箱；该冰柜自己的昼夜切换返鲜行为保持原样 |
| 储藏室（新地窖），`storeroom`（工坊 2784048339） | 标准储物接口，按当前 `preserver` 保鲜/返鲜倍率或 `fridge` 标签排序 |
| 其他冰柜、地窖和储藏模组 | 自动识别固定储藏建筑的标准 `container`，读取 `preserver:GetPerishRateMultiplier(item)`、`fridge` 或 `foodpreserver` |
| 其他模组烹饪锅 | 具有标准 `stewer`、1–16 格 `container`，且在 `cooking.recipes` 中注册；实际食材限制由锅本身决定 |

冰柜的排序值仅决定存放优先级，不会改变其实际腐败速度。无法通过公开保鲜组件或标签判断的自定义保鲜逻辑，按普通储藏处理，仍可收放；完全自定义、无标准 `container` 的地窖需要额外适配。不同地窖的“保鲜开关/倍率”仍由各自模组控制，不会被强制覆盖。

为特殊容器提供排序扩展（数字越低优先级越高）：

```lua
require("nac_storage").RegisterPreservation("your_cellar", 0)
-- 或 function(container_entity, food_entity) return rate end
```

自动烹饪没有玩家施作者，不额外触发角色烹饪技能或食谱解锁。建议同一口锅只交给一个自动烹饪模组管理；本模组不复制“馨食记”的菜谱规划或食谱书界面。

## 保存与卸载

数量偏好、当前配方、剩余锅数及正在制作的收存任务随每口锅保存，读档后继续。旧版已暂停的任务保持暂停。锅内正在烹饪的食物仍由游戏原生 `stewer` 保存。

拆掉再重建锅、将便携锅收起再部署，视为新锅，需要重新设置。卸载模组后锅、食材和已做好的料理保持原版行为，自动化停止。

洞穴与地面分片需分别启用模组。专服的 `modoverrides.lua` 示例（合并进已有 return 表，不替换其他条目）：

```lua
["nearby_autocook"] = {
    enabled = true,
    configuration_options = {
        SEARCH_RADIUS = 12,
        GROUND_INGREDIENTS = true,
        CHECK_INTERVAL = 1,
        TRANSFER_FX = true,
    },
},
```

## 开发与验证

`python tools/build_release.py`：在 `dist/` 生成干净的工坊目录、ZIP 和 SHA-256 校验文件；运行时脚本、文档及预览图进入安装包，测试、发布工具、Git 数据和第三方游戏源码不进入安装包。

`python nearby_autocook/tests/run_tests.py`：Lua 5.1 语法、真实原版 Container/Stackable 储物行为、客户端界面交互和服务端 RPC 边界。需要 Python + `lupa`；可用 `DST_SCRIPTS_PATH` 指向自行提取的游戏 `scripts`。

`python nearby_autocook/tests/run_game_smoke.py --compat`：新建独立离线世界，加载实际 Arcadiea 冰柜和储藏室模组，运行原生锅、有限锅数、鲜度、多份成品、暂停、存读档与实际调度连续出餐。需要本机已下载上述两个工坊条目。`--caves` 可测试洞穴。测试不会读写既有世界。

界面自动化验证为交互逻辑检查；实际多人客户端的界面观感与飞行动画仍需进入游戏确认。原版游戏脚本和第三方模组不随安装包分发。

1.0.0 已通过地面兼容及独立洞穴引擎测试。1.0.1 的地面兼容引擎已通过 25 项及实际连续两锅，包含打开储藏容器取料/存入、使用原版烹饪键按数量续做和配方自动更新。界面 13 项、储物 15 项、服务端 RPC 10 项及飞行组件 8 项均通过。8 距离飞行的原生引擎对照连续采样 49 帧，参考食材与生产特效的最高点均为 10.820979，逐帧高度最大偏差为 0.000000。

1.0.2 已通过 66 项逻辑检查（界面/动作 25、RPC 18、储物 15、飞行 8），以及 33 项真实游戏引擎用例、实际连续两锅和原生飞行对照。新增覆盖烹饪锁锅时右键入口、缩短/延长数量、连续转有限、取消后收存本锅、换配方、缺料等待管理及修改/取消后的读档。
